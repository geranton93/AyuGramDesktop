# Local quality-gate plan

This repository uses a versioned Git hook as a fast local guardrail. Enable it once
in each checkout:

```bash
git config --local core.hooksPath .githooks
```

The setting is local Git configuration and is not committed. The hook itself is
tracked in `.githooks/pre-commit` and delegates to
`Telegram/build/checks/pre_commit.sh`.

## Required tools

The hook intentionally fails closed when a required analyzer is needed for the
files being committed. On macOS with Homebrew, install the available baseline:

```bash
brew install gitleaks actionlint shellcheck osv-scanner
```

`git`, `bash`, `rg`, `python3`, and `openssl` are also required for the matching
checks. The hook never prints scanner output by default. For a local diagnostic run,
keep its temporary logs outside the repository:

```bash
AYUGRAM_PRECOMMIT_KEEP_LOGS=1 git commit
```

The output will identify the temporary directory; do not copy those logs into a
commit because scanners can include matched secret material even when redaction is
enabled.

## What runs before a commit

The checks are staged-snapshot based. A file with unstaged edits is never silently
used as a substitute for the staged blob during syntax, trust, or secret checks.

| Change | Mandatory gate |
| --- | --- |
| Any staged file | unresolved conflict, whitespace/patch check, sensitive filename policy, high-confidence secret patterns, Gitleaks staged scan |
| GitHub Actions workflow | actionlint; zizmor with `AYUGRAM_PRECOMMIT_STRICT=1` or when installed |
| Shell script | ShellCheck on the staged content |
| Python, JSON, or XML | syntax/well-formedness parse on the staged content |
| Updater trust files | Ed25519 root-manifest verification with OpenSSL |
| Remote-config trust key | Ed25519 public-key validation with OpenSSL |
| Dependency manifest or lockfile | OSV-Scanner with transitive resolution disabled |
| Updater feed or remote-config tooling | focused feed and signing unit tests |
| Version metadata/parser | adversarial parser tests for duplicate keys, unknown keys, extra fields, and shell metacharacters |

The release/deploy scripts are also checked for unsafe `eval` and unquoted
version-field expansion. Version metadata is parsed by
`Telegram/build/version_parser.sh`, which uses an allowlist and strict value formats.

## Optional full local gate

The hook does not build the large Telegram target on every commit. When the existing
compiled Debug test binaries are available, require them explicitly:

```bash
AYUGRAM_PRECOMMIT_FULL=1 git commit
```

This runs the updater trust/contract test and the Premium-promotion policy test from
`out/updater-test-xcode/Debug`. A missing binary is a failure in this mode, so it
cannot be mistaken for a passing test.

For a workflow change, install `zizmor` when possible and use strict mode to make
its absence a failure:

```bash
AYUGRAM_PRECOMMIT_STRICT=1 git commit
```

`semgrep`, `trufflehog`, `detect-secrets`, `clang-tidy`, and SBOM tools remain
supplementary rather than mandatory in this hook. They are useful in a scheduled
or CI job, but making an unavailable or network-dependent tool a local hard gate
would create false confidence or block unrelated commits. `semgrep` was not made a
gate here because the current machine's certificate store prevents it from starting.

The remote configuration uses a separate pinned Ed25519 key from the update
manifest. The signing private key is never generated by the client build and is
not stored in GitHub Actions or this checkout; only the operator that publishes
the two remote-config endpoints needs it.

## Safe operating rules

Never use `git commit --no-verify` for a release or security-sensitive change.
Review `git diff --cached --stat` and `git diff --cached --name-status` before
committing. If a scanner reports a candidate, inspect the staged line and classify
it; do not add a broad allowlist just to make the hook green. Public Telegram test
identifiers and the updater's public root key are not private credentials, but
private signing keys, API hashes belonging to an operator, access tokens, passwords,
certificates with private material, and account/session data must remain outside
the repository.

The hook is a local guardrail and can be bypassed by a user with write access to the
checkout. For release protection, the fork should also require successful GitHub
Actions checks and review on `dev`; local hooks alone are not a server-side policy.
